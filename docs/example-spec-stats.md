# Feature Specification: `/stats` Command

## 1. Summary
This specification details the implementation of a unified `/stats` command designed to provide real-time visibility into the application's operational state. The feature will be accessible via two interfaces: the CLI Read-Eval-Print Loop (REPL) and the Discord Bot (via a slash command).

The command will aggregate and display four key categories of data:
1.  **Session Analytics:** Uptime, command count, and error rates.
2.  **Token Usage:** Total input/output tokens consumed during the session.
3.  **Codebase Index Count:** Number of files and vector chunks currently indexed.
4.  **Model Router Status:** Active model provider, health status, and rate limit availability.

## 2. Functional Requirements

### 2.1 Data Collection
The system must maintain a runtime state object that tracks the following metrics incrementally:
*   **Session Start Time:** Timestamp when the application initialized.
*   **Interaction Count:** Total number of user prompts/commands processed.
*   **Token Counters:** Cumulative `prompt_tokens` and `completion_tokens`.
*   **Error Count:** Number of failed API calls or internal exceptions.

### 2.2 CLI REPL Behavior
*   **Trigger:** User types `/stats` or `stats` in the REPL prompt.
*   **Output:** A formatted ASCII table or structured text block printed to `stdout`.
*   **Format:** Monospaced font alignment for readability using `picocolors`.

### 2.3 Discord Bot Behavior
*   **Trigger:** User invokes the `/stats` slash command.
*   **Output:** An `Embed` object sent to the channel.
*   **Formatting:** Use Discord Embed fields to separate the four data categories. Use color coding (e.g., Green for healthy status, Red for errors).

## 4. Acceptance Criteria

### Scenario A: CLI Usage
1.  **Given** the application is running and the REPL is active.
2.  **When** the user types `/stats`.
3.  **Then** the system displays a formatted table containing session uptime, token counts, indexed files, and active model status.

### Scenario B: Discord Usage
1.  **Given** the Discord bot is online.
2.  **When** a user types `/stats` in a channel where the bot has access.
3.  **Then** the bot replies with a formatted Embed displaying session analytics.
